# popup の UX 設計 — 権限・リロード・ショートカット

実機で報告された 4 症状を code から裏取りし、popup を「操作の一覧」から
「状態の表示」へ作り直すための設計。

---

## 1. 何が起きているのか (実挙動マトリクス)

| # | 状況 | インスペクト | ツリー | 再描画 | リロード |
|---|------|:---:|:---:|:---:|---|
| A | localhost を開いた直後 | ○ | ○ | ○ | 不要 |
| B | 本番サイトで「現在のサイトで有効化」→ 同じタブ | ○ | **×** | **×** | ツリー/再描画のみ必須 |
| C | 同じオリジンの**既に開いていた**別タブ | × | × | × | 必須 |
| D | 有効化したオリジンを新しいタブで開く | ○ | ○ | △ 明滅のみ | 不要 |
| E | 「全サイトで許可」→ 同じタブ | ○ | **×** | **×** | ツリー/再描画のみ必須 |
| F | 全サイト許可済みで新しいサイトを開く | ○ | ○ | △ 明滅のみ | 不要 |
| G | 全サイト許可済みで**既に開いていた**別タブ | × | × | × | 必須 |

### なぜ B/E でツリーと再描画が動かないのか

React は**自分のモジュール評価時に一度だけ** `__REACT_DEVTOOLS_GLOBAL_HOOK__` を掴みます。
`injectInternals` はフックが無ければ `false` を返して**二度と再試行しません**。

`executeScript` による mid-page 注入は React のマウント後に走るので、後から `installHook` しても
`onCommitFiberRoot` は永久に来ません。結果 `hookState.roots` が空のままで、
`buildTree` は `[]` を返し、`RenderDebugger` の `onCommit` 購読も発火しません。

一方インスペクトは `getFiberFromElement` が DOM の `__reactFiber$` を直読みするのでフック不要です。
**つまり「リロード不要」はインスペクトにだけ成立します。**

## 2. 報告された 4 症状の正体

### 症状 1「毎回許可が必要かもしれない」

原因は 2 つあり、どちらも実在します。

1. **unpacked 拡張の ID は展開先の絶対パス由来。** `PUBLISHING.md` の配布方式 A は
   「zip を解凍して読み込む」なので、バージョンごとに別フォルダへ解凍すると**別拡張扱い**になり、
   過去の許可も動的登録も全部消えます。manifest に `key` フィールドが無いため確実に起きます
2. **popup が `permissions.contains` を見ていない。** 許可済みでもボタンの文言・色・状態が
   まったく変わらないので、ユーザーは毎回押す = 毎回許可作業をしている感覚になります
   (実際には Chrome は許可済みオリジンの `request` を無言で true 解決するのでダイアログは出ません)

### 症状 2「全サイト許可がグローバルに効いていないかも」

**実体は G 行です。** 動的登録した content script は**既に開いていたタブには遡及しません**。
新しく開いたタブ (F) では正しく効きます。つまり「効いていない」のではなく
「開きっぱなしのタブ群が無反応のまま残る」が正しい理解です。

副次的な原因候補も 2 つあります。`registerContentScripts` の失敗が空 `catch` で握り潰されること、
Chrome 側の「サイトへのアクセス: クリックしたときのみ」設定が host 権限を保留にすることです。

### 症状 3「リロードが必要なのに『リロード不要』と書いてある」

**文言が誤りです。** インスペクトについては真ですが、ツリー・再描画については偽。
該当箇所は 4 つあり、いずれも機能を限定しない書き方になっています。

### 症状 4「ショートカットが最初は効かない」

2 つの別物が混ざっています。

1. **未注入タブでは無音**。`background` → `tabs.sendMessage` が receiver 不在で reject し、
   `.catch(() => {})` で完全に握り潰されます。押しても文字どおり何も起きず理由も出ません
2. **再描画の可視化が `(未設定)`**。⌥⇧R を Screencastify が予約済みで、Chrome が割り当てを
   拒否しました。popup は実バインドを正しく読めていますが、**未設定を検知しながら修復導線を
   出していません**。しかも唯一の修復ボタンは既定で閉じた「Advanced」の中にあります

## 3. 設計方針

> popup が開くたびに (権限スコープ × 注入実態 × ショートカット健全性) を測り、
> そこから「今使えるもの / 使えない理由 / 次の一手」を導出して描画する。

導出は純関数 (`src/popupState.ts`) に切り出して vitest で固め、UI は描くだけの薄い層にします。

### 状態モデル

```ts
type Scope     = 'unsupported' | 'none' | 'origin' | 'all';   // どこまで許可されているか
type Injection = 'absent' | 'partial' | 'full';                // content script が居るか、間に合ったか
type ModeAvail = 'ok' | 'needs-enable' | 'needs-reload' | 'unsupported';
```

可用性の導出ルール:

```
scope === 'unsupported'  → 全モード unsupported
injection === 'absent'   → scope==='none' なら needs-enable / それ以外は needs-reload
injection === 'partial'  → inspect: ok / tree: needs-reload / render: needs-reload
injection === 'full'     → 全モード ok
```

**`partial` の行が今回の肝**です。「リロード不要」がインスペクトにだけ成立することを
型で表現し、文言と UI の両方をここから駆動します。

`injection` の判定には、`hook.ts` に `earlyInstall: document.readyState === 'loading'` を
1 行足し、`earlyInstall || roots.size > 0` を `full` の条件にします。
状態の取得は `design-scan` の往復パターン (bridge のタイムアウト付き `sendResponse`) を
そのまま複製すれば済みます。

### 画面構成

```
① STATUS CARD (常設)      ← 新規。「今どうなっていて、次に何を押すか」を 1 行で
② SHORTCUT 警告           ← 新規・未設定があるときだけ
③ MODES (可用性バッジ付き)
④ ACCESS (現在のサイト / 全サイト)   ← ③ の下に降格
⑤ TOKENS → ⑥ DISPLAY → ⑦ AI → ⑧ Advanced → ⑨ Help
```

主要な状態遷移:

| scope / injection | primary ボタン |
|---|---|
| `none` / absent | **[このサイトで有効化]** |
| 許可済み / absent | **[このページをリロード]** (許可はあるのに script が居ない = リロードが唯一の修復) |
| 許可済み / partial | **[インスペクトを開始]** + secondary [リロード] |
| 許可済み / full | **[インスペクトを開始]** |
| inspect ON | **[インスペクトを停止]** |

**2 つの許可ボタンの関係を UI で表現する**のが症状 1・2 への回答です。
`scope === 'all'` のとき「現在のサイトで有効化」は**非表示**にし、
「このサイトは全サイト許可の対象です」と出す。`scope === 'origin'` なら
ラベルを「このサイトは許可済み」に変えて disabled にする。
これで冗長な per-origin リクエストが構造的に起きなくなります。

### リロードボタンは出す。ただし自動リロードはしない

`chrome.tabs.reload` は追加権限なしで呼べます。ただし対象はデザイナーが検査中の実ページなので、
フォーム入力・スクロール位置を無断で破棄するのは許容できません。**押下は必ずユーザー起点**にし、
押した直後は `window.close()` せずに「リロード中…」へ差し替えます
(無言 close は今回の不信の元凶なので繰り返さない)。

### ショートカット未設定の能動誘導

`applyShortcutHints` を戻り値付きに変え、`key === ''` を数えます。1 件以上で ② を表示し、
「3 個中 1 個が未割り当て — 既定キーを Chrome が確保できませんでした。他の拡張が使用中の
可能性があります」と出して、**`#configureShortcuts` を Advanced からトップレベルへ移動**します。

## 4. 実装の分割 (この順に単独で出せる)

1. **文言の嘘を消す** — コード変更ゼロ。**実施済み**
2. **ショートカット警告 + ボタン移動** — 状態往復に依存しないので独立して出せる
3. **`scope` 判定** (`permissions.contains` を per-origin でも見る) — 症状 1・2 が消える
4. **`status` 往復 + `deriveView`** — 症状 4 と「押しても何も起きない」が消える。ここが本丸
5. **オンボーディング** (`onInstalled` + `seenOnboarding` フラグ、popup 内に 3 文 + 1 ボタン)

合計 ~450 行、1 セッション相当。うち 200 行超が既存パターンの複製と純関数 + テストで、
新規の設計判断は状態モデル 1 つだけです。

## 5. 併せて直すべき小さな不整合

- 空ツリーに `statsEmpty`「再描画は記録されませんでした」が出る (ツリー用の文言ではない)
- mid-page 注入では `hookState.devMode` が必ず false になるため、dev サーバ相手でも
  常に「開発ビルド未検出」トーストが出る (バッジ側は Fiber から個別判定するので実害は文言のみ)
- 全サイト解除が `dyn_*` の登録を残す
- `#siteStatus` が 2 つのボタンの共用領域で、どちらの結果か判別できない
- blob タブで全サイト未許可のとき「有効化できません」と出る (正しくは「全サイト許可が必要」)

## 6. 配布方式に起因する問題 (公開すれば解決する)

症状 1 の主因である「拡張 ID がパス由来で変わる」は、**Chrome Web Store で公開すれば消えます**
(ストア版は ID が固定)。ローカル zip 配布を続ける場合は、`manifest` に `key` を入れて
ID を固定するか、展開先パスを固定する運用が要ります。
